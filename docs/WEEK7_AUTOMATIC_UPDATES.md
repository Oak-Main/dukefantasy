## Evidence gate contract

The evidence file has `week:7`, `baseCommit` (exact 40-character commit), `observations` and optional `moduleReviews`. Use the pure `collectFacts` function in `scripts/week7-evidence.mjs` on the before/after bundles to enumerate changed factual records. Each observation has kind, key, normalized value and sources. Every source has HTTPS url, actual checkedAt, reportedWeek matching that record (7 for current injury/inactive reports), and the normalized value actually observed. The two source values must match the candidate; retrievals must be within two hours of preflight. Historical score corrections need the historical game's actual week. Removed records require removalReason and two explicit source confirmations; absence from a feed is not recovery evidence.

For a source-date change, a module review is also required: module (`schedule`, `injuries` or `inactives`), sourceAsOf matching that module's date, dataSha256 from `digest` of that module's collected facts, and two sources each confirming `{dataSha256, complete:true}` for the full reviewed set. Record the actual fetchedAt on the module. This records the researcher's complete comparison attestation; the gate validates recorded evidence consistency, not the truth of an unread webpage. Actual live research remains mandatory. Metadata-only false freshness and unclaimed changed facts fail closed.

## Checks and deployment

`npm run week7:preflight` requires the evidence gate, full `npm run verify`, fresh `dataset:verify`, production dependency audit, Cloudflare types and a Wrangler dry run. `npm run week7:deploy` runs that preflight, deploys the checked build and runs `scripts/smoke-release.mjs` against the public domain. Preserve production flags and all commercial kill switches. No deployment for a source conflict, invalid data, failing test, failed audit, stale evidence or another active writer.

## Handoff and limitations

Inputs: committed NFL data, source register, official game/club reports and current corroborating publishers. Assumptions: Week 7 only, public sources, local host availability and existing authorized credentials. Decisions: agent research with explicit evidence, separate module dates, serialized publication and fail-closed checks. Deliverables: this runbook, the evidence gate and tests, native inactive renderer, per-module provenance and two bounded thread schedules. Acceptance requires passing local/release checks and successful schedule creation; final setup evidence is recorded in the task output. The site operator owns host availability, credentials and unresolved-source decisions; the scheduled agent owns research, checks, publication and recovery within the authorized scope. Local schedules cannot run while the host/app is unavailable, and two-source publication may lag an initial single-source report.
