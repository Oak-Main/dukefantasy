# Assumptions register

| ID | Assumption | Rationale | Risk/mitigation |
|---|---|---|---|
| A-001 | The repository is a new project. | It contained no project files or Git history before initialization. | Preserve the generated Vinext foundation and document all migration choices. |
| A-002 | This delivery uses deterministic fixture data. | No provider contracts, credentials, or content rights were supplied. | Label every fixture surface as demo; noindex demo content; expose provider configuration state. |
| A-003 | “CFB Apex” is the approved release brand for `cfbapex.com`. | The owner selected the domain and requested deployment there. | Keep brand strings and metadata centralized so future changes remain consistent. |
| A-004 | Clean Mode is the device default. | Required product principle. | Persist only an explicit local preference; gate Odds & DFS Mode with disclosure. |
| A-005 | `cfbapex.com` and `www.cfbapex.com` are authorized for a public fixture beta; campaign, affiliate, paid-data, and live-data activation are not. | The owner explicitly requested the domain deployment, but supplied no provider contracts or launch evidence. | Keep the fixture/noindex boundary and all commercial/live activation environment-gated. |
| A-006 | Public examples may use invented fixture schools and people. | Avoids false claims and licensing issues. | Mark them as deterministic demonstration records and never present them as live/current. |
| A-007 | The current runtime supports four concurrent agent threads. | Platform limit is four, below the brief’s preferred 6–8. | Use three parallel specialists plus the managing thread and sequence later reviewers. |
| A-008 | The domain release is an unauthenticated fixture beta, not a production live-data launch. | The owner authorized a public URL before provider and legal gates were closed. | Retain global noindex, synthetic labels, server-side kill switches, and lightweight public endpoints only. |
| A-009 | Fixture transformations are product demonstrations, not predictive models. | No licensed historical corpus, trained artifact, calibration, or backtest was supplied. | Use synthetic provenance and candid model cards; never market accuracy claims. |
| A-010 | One client-side product shell is acceptable for this preview. | It provides coherent interactive fixtures quickly. | Split routes and reduce client JavaScript before a public performance launch. |
| A-011 | The supplied July 31 research report is discovery input, not authoritative data. | It contains material conflicts with current primary sources. | Quarantine unsupported facts; use `docs/RESEARCH_REPORT_AUDIT.md` before implementation. |
| A-012 | Sportradar and SportsDataIO are RFP candidates, not selected vendors. | No signed order form, SLA, credentials, or pilot evidence was supplied. | Compare identical written rights/coverage responses and measured replay/live results. |
| A-013 | An external persistent-stream relay may not be necessary. | Current Workers docs allow unlimited HTTP wall time while connected; lifecycle reliability still needs testing. | Prototype on Cloudflare first and add a minimal relay only on measured need. |
| A-014 | Public live-data launch remains explicitly unauthorized. | Domain deployment approval does not supply rights, entity crosswalk, shadow pilot, drills, staffing, or legal approval. | Deny-by-default environment gates, noindex lock, fixture beta, and public live-launch runbook. |
| A-015 | The 2026 NFL regular season is 18 weeks, 272 games, 17 games per team (one bye each), and ESPN's `week.number` is authoritative for week membership. | Confirmed against ESPN's season calendar and a full week-keyed pull on 2026-10-11 (0 week disagreements with the previous date-bucket heuristic). | `build-nfl-dataset.mjs` throws on any other shape; `tests/schedule-integrity.test.ts` pins it. A future season with a different structure must update `GAMES_PER_TEAM`. |
| A-016 | The site speaks US Eastern; ESPN indexes a game under its ET calendar day. | `lib/nfl-scoreboard.ts` already documents the ET-day indexing; every consumer regex-extracts "h:mm AM/PM ET" from `kickoffLabel`. | The build converts with the IANA zone (EDT/EST automatic). The independent test oracle hard-codes the 2026-27 DST instants and must be extended for a new season. |
| A-017 | A deploy is the data refresh; the live feed (`/api/nfl-scoreboard`) overlays only the ticker, the homepage finals strip, and (D-020) the scoreboard, schedule, game header, and team schedule. | `lib/cfb-dataset.ts` and the watch board, conference hubs, and homepage week and marquee cards read the baked snapshot; there is no scheduled rebuild in the repository. | Redeploy after each game window; the overlay only repairs games inside the route's window (A-023). `npm run dataset:verify` reports when the snapshot is behind ESPN. |
| A-018 | Editorial boards are "current" by cadence, not by calendar date. | Start/Sit and Trade cover the week in play; Waiver is published Tuesday for the following week; Rookie usage is published Tuesday for the week just completed. | `deskBoardStatus` encodes this; update it if the publishing cadence changes. |
| A-019 | Team records on the NFL homepage are tallied from final scores in the ESPN schedule the dataset builder fetches. | The builder derives `standings` from the schedule it already fetched; `npm run dataset:verify` compares them with ESPN's official standings. | A game missing from the schedule skews two teams. The builder's 272-game gate and `dataset:verify` catch it; the lane labels its basis and as-of date. |
| A-020 | A national or primetime window means NBC, ESPN/ABC, Prime Video, or Netflix, identified by network name. | Network is the stable signal; kickoff times move under flex scheduling from Week 5. | Regional CBS/FOX and NFL Network windows are not preferred. Revisit if the product wants a time-of-day definition. |
| A-021 | The homepage marquee is chosen from a build-time snapshot of the week. | Per A-017, the homepage marquee and week cards do not read live scores; the pick stays deterministic. | A game can be under way by the time a visitor reads it. The later-kickoff tiebreak lowers, but cannot remove, that chance. |
| A-022 | ESPN event ids in `/api/nfl-scoreboard` are the ids the dataset build bakes into `Game.id`. | One-off manual check against the live feed on 2026-10-11: 14 of 14 events matched baked ids, including a game in progress. | A mismatch can only fall back to the baked row, never patch the wrong game. `tests/live-scoreboard.test.ts` pins id-only matching and the `eventId` on every team-schedule row. |
| A-023 | The route's window (ET today minus two days through tomorrow) covers every game the overlay needs to repair. | The route fetches four scoreboard days; older games never appear in the feed. | A game that finished before that window and after the last deploy stays at its baked state until the next deploy. Redeploy after game windows, or widen the route window if deploys lag. |
| A-024 | An in-progress score that no poll has confirmed for five minutes is more misleading than the baked row. | AGENTS.md: never imply stale information is live fact. Polls are 60 seconds and the route plus browser caches add up to about 90 seconds. | `LIVE_STALE_MS` in `lib/live-scoreboard.ts`; tune from observed ESPN reliability. |
| A-025 | Records, standings, conference tallies, the watch board, and the homepage week and marquee cards stay dataset-as-of; only the scoreboard, schedule, game header, team schedule, ticker, and finals strip overlay live scores. | Recomputing records from a partial overlay is inference, and a game could be counted twice. The other surfaces were outside this change. | Those surfaces lag until the next deploy and say "Dataset as of" on the page. Extend the overlay per surface with `useLiveScoreboard` when needed. |
| A-026 | Renderers and viewers run in arbitrary time zones; only the Eastern calendar is meaningful for game days. | The Worker renders in UTC and US viewers are UTC-4 to UTC-8: a bare `new Date("2026-10-11")` printed "Sat, Oct 10" in Eastern, Central, Mountain and Pacific. `tests/rendered-html.test.mjs` renders a game page under `TZ=America/Los_Angeles`. | A component that parses a date-only string without `timeZone: "UTC"`, or compares an Eastern day with a UTC day, brings back off-by-one days for US viewers. Use `easternDay()` for "today" and noon-UTC calendar formatting for dates (D-022). |
